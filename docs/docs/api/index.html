API reference

API reference

Generated from the docstrings of rdr 0.1.0: signatures, defaults and one description per parameter. Parameters that most calls never change are folded under Advanced parameters.

Retriever & encoder

The entry point: load RDR-8B (or any sentence-transformers model), build an index, search and read out.

rdr.RecursiveRetrieverRecursive dense retrieval with one instruction-conditioned encoder.rdr.EncoderQuery/document encoder built on a SentenceTransformer.rdr.load_sentence_transformerLoad a SentenceTransformer.

Prompts & instructions

How states are rendered to text: instructions per role, the observation layout and the paper's presets.

rdr.PromptConfigInstructions and text layout of all states.rdr.ContextLayoutHow the observed documents of a state are written.rdr.StateRendererRenders states to text with a PromptConfig and an optional token-level truncation.rdr.instructions.getInstruction by key (recovery, continuation, recovery_multihop, multihop …).rdr.instructions.root_forThe paper's root instruction for a benchmark/task, e.g. root_for("bright", "biology").

Index

Exact inner-product search over the cached document vectors, on GPU (fp16) or CPU.

rdr.DenseIndexExact inner-product (= cosine) search over normalized document embeddings.

Search strategies

Which states form. Every strategy is read out by the global readout unless another readout is requested.

rdr.DenseSearchPlain dense retrieval: one encoder call, one lookup (RDR(1,0), q0).rdr.TreeSearchRDR(H, b): from the root, every state selects up to b candidates; each selection becomes a child that appends the document to its parent's observations.rdr.ChainSearchA single chain of H states: TreeSearch(H, branching=1).rdr.BreadthSearchShallow breadth RDR(2, m): the root and m independently observed candidates (Eq. 4), 1 + m encodings in two dependent rounds.rdr.BeamSearchBeam search over observation paths, as in MDR / BeamDR (Appendix H.1).rdr.DocAsQuerySearchDocument-as-query expansion (COR-style, without COR's LLM aspect queries): same geometry, eligibility and deduplication as TreeSearch, but each child searches with the selected document's own index vector instead of an encoded state (Table 32).rdr.JointFeedbackPseudo-relevance feedback as in ANCE-PRF: the query and the root's top-m documents are encoded jointly into one second query vector, read out alone (StateReadout(level=2)).rdr.make_searchA search strategy from a name or a dict, e.g. make_search({"name": "beam", "width": 13}).

Readouts

How the states' scores become one ranking. Grouped as global, realized paths, fusion rules, model-based and views.

rdr.GlobalReadoutLevel-balanced aggregation of sparse per-state score distributions (RDR's default readout).rdr.RootReadoutThe root query alone, RDR(1,0) / q0: its raw cosine ranking.rdr.PathProductscore(d) = max over selections of d of prod_i l_i — the product of the selecting scores along the path (raw cosines, or min–max scores for TreeSearch(path_score="minmax")).rdr.ChainOrderComplete chains in hop order, as returned by beam retrievers.rdr.SequenceSumMDR's sequence score: complete chains ordered by the sum of raw cosines (ChainOrder("sum")).rdr.ProbabilityChainBeamDR's probability chain: complete chains ordered by the product of state softmax probabilities (ChainOrder("logprob")).rdr.TerminalStateThe last state of a chain alone (its raw cosine ranking). With several deepest states the one with the best path score is used.rdr.SelectedSetThe realized set E in selection order (TreeHop-style union output).rdr.RRFReciprocal rank fusion of the states' ranked lists, 1/(k + rank) with ranks from 1.rdr.PostOrderRRFCOR-style post-order aggregation: each node's list is RRF-fused with its children's fused lists (recursively, leaves first) and the root's fused list is the output.rdr.BordaBorda count over the states' top-K lists: K - rank + 1 points per state.rdr.CombMNZ(sum of normalized scores) x (number of states whose top-K contains the document).rdr.MaxOverStatesmax_s p_s(d): the best normalized score any state gives the document.rdr.StateReadoutRanking of the state at level (default: the deepest) — e.g. joint feedback, or the terminal state of a chain. With several states at that level the one with the best path score is used.rdr.RootInterpolationDC-PRF's readout on a chain: one extra lookup with normalize(lam * z_root + (1 - lam) * z_last).rdr.AssemblySet-conditioned selection (Appendix I.1, Eq. 10).rdr.ZAgreementFuse the readouts of two (or more) views of the same traversal by z-agreement (Eq. 5–9).rdr.recovery_fusion+ recovery (z-agreement) of Table 1: the primary global readout fused with the recovery view.rdr.recovery_view_readoutThe recovery view read out alone, as in the paper's evaluation code (Table 20, "recovery alone"): every recovery state contributes a sparse softmax of its full-column min–max scores, summed without level balancing and without the root.rdr.make_readoutA readout from a name or a dict, e.g. make_readout({"name": "rrf", "k": 60}).

Evaluation

The metrics of the paper (Recall@k over gold groups, binary nDCG@k, α-nDCG@k) and the benchmark loaders of reproduce/.

rdr.evaluation.recall_at_kFraction of gold groups with at least one member in the top-k.rdr.evaluation.ndcg_at_knDCG@k. graded=False (default) uses binary gains for every rel > 0, as the paper's evaluation does; graded=True uses the relevance value as a linear gain (pytrec_eval style).rdr.evaluation.alpha_ndcg_at_kalpha-nDCG@k (novelty-aware; BRIGHT-Pro). aspects maps doc -> iterable of aspect ids.rdr.evaluation.macroMean over groups of the per-group means (task/group macro average).rdr.evaluation.benchmarks.TaskOne evaluation task (a corpus with its queries).rdr.evaluation.benchmarks.load_nanobeirNanoBEIR (13 tasks) from sentence-transformers/NanoBEIR-en; queries without qrels are dropped.rdr.evaluation.benchmarks.load_brightBRIGHT (12 domains) from mteb/BRIGHT at the pinned revision, with its excluded ids.rdr.evaluation.benchmarks.load_coirCoIR (10 datasets, 20 subsplits); parent is the dataset of the official 10-dataset macro.rdr.evaluation.benchmarks.load_toolretToolRet: one tool corpus, 35 query groups (macro-averaged), per-query instructions.rdr.evaluation.benchmarks.load_topiocqaTopiOCQA with the paper's 1M-passage corpus (queries.json + corpus.jsonl in data_dir).rdr.evaluation.benchmarks.load_multihopMuSiQue (support), BrowseComp+ (evidence), FanOutQA and FRAMES (source groups) from prepared files.
