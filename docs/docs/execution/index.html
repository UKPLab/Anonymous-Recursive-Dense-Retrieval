Running at scale

Devices & batching

Almost all query-side time is encoding: every state is one forward pass over the instruction, the query and the observed documents. The exact index search takes well under a millisecond per state.

Per question, from Table 18 of the paper: one process per A100-80GB, the states of a level encoded as one batch, exact GPU search over the cached index. Deeper levels cost more because each state carries up to three documents.

Devices

python
from rdr import RecursiveRetriever

# one GPU for the encoder, one for the index and the exact search
retriever = RecursiveRetriever("RDR-8B", encode_device="cuda:0", index_device="cuda:1")

# data-parallel encoding over two GPUs, index on a third
retriever = RecursiveRetriever("RDR-8B", encode_device=["cuda:0", "cuda:1"], index_device="cuda:2")

# everything on one GPU, or on CPU (fp32; slow for an 8B encoder)
retriever = RecursiveRetriever("RDR-8B", encode_device="cuda:0", index_device="cuda:0")
retriever = RecursiveRetriever("RDR-8B", encode_device="cpu", index_device="cpu", torch_dtype="float32")
  • encode_device: where the encoder runs; a list gives one replica per device (data-parallel, threaded).
  • index_device: where the document vectors live and the exact search runs. On GPU the index is fp16 (1M documents × 4096 dimensions = 8.2 GB), on CPU fp32.
  • Query vectors are cast to the index dtype; scores are computed in query chunks (about 512 MB per score block), so memory stays flat for large batches.

Batching

The search is level-synchronous: all states of one level, across the queries of a batch, are rendered and encoded together, then searched together. A tree of depth 4 therefore needs four dependent rounds regardless of how many states a level holds.

python
retriever = RecursiveRetriever(
    "RDR-8B",
    query_batch_size=32,   # queries searched together, level by level
    batch_size=8,          # encoder micro-batch of rendered states
    inflight=2,            # query batches in flight: encode one while another is searched
)

With separate encode and index devices, inflight=2 keeps both busy: while one query batch is encoded, the next is searched.

Exact reproduction

bf16 embeddings depend slightly on which texts share a batch. The default batching sorts states by length for speed. To reproduce the paper's batch composition, encode in the given order with fixed batches and group states as the paper's runs did:

python
from rdr import Encoder, RecursiveRetriever

encoder = Encoder("RDR-8B", batch_size=8, sort_by_length=False)   # fixed consecutive batches
retriever = RecursiveRetriever(
    encoder, prompts="multi-hop",
    encode_grouping="query",   # multi-hop runs: states grouped per query; single-hop runs: "slot"
    query_batch_size=10**9, inflight=1,
)

reproduce/run.py --exact sets these options. See Reproducing the paper.

Index, caching and exclusions

python
from rdr import DenseIndex

index = retriever.build_index(corpus, cache_dir="cache/musique-rdr8b")  # encoded once, loaded next time
index.save("my_index")                                                  # or save / load explicitly
index = DenseIndex.load("my_index", device="cuda:1")

excluded = [index.positions(ids) for ids in excluded_ids_per_query]      # corpus ids -> index positions
hits = retriever.search(queries, index, exclude=excluded)
A cache directory is not validated against the corpus or the model: use one directory per corpus and model. Saved ids are strings.

Chunked corpora

If several index entries belong to one document, pass groups= (one document key per entry) to build_index. Readouts then max-pool chunk scores per document. In the paper's four multi-hop suites every index entry has its own id; FanOutQA and FRAMES credit any passage of a relevant source group at the metric level instead (recall_at_k over gold groups).
