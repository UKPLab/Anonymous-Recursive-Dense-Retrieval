Search strategies

Tree search, RDR(H, b)

The root is level 1 and has an empty context. Every expandable state selects up to b eligible documents. Each selection becomes a child, which appends that document to its parent's observations. With H levels a tree holds at most 1 + b + … + bH−1 states: 40 for RDR(4, 3), the operating point of every task in the paper.

How a level is expanded

All states of a level are rendered and encoded in one batch, and each retrieves its top-K candidates (200 by default). Selection then picks each state's b best eligible candidates. The selections of the deepest level are recorded, since realized readouts use them, but they are not encoded. The readout always sees each state's full top-K, eligible or not.

Which candidates are eligible: dedup

dedup sets the selection rule. The multi-hop presets use "level": documents selected at earlier levels are blocked, and when two states of a level propose the same document, one selection remains (the one with the higher path product). The single-hop protocol uses "none": every state picks its own top-b, so all 40 states form.

Multi-hop presets use "level": branches that propose the same document merge, so fewer than the maximum 40 states of RDR(4, 3) are realized. The single-hop preset uses "none": all 40 states.

rdr.TreeSearch

"tree"guide[source]
classrdr.TreeSearch(depth=4, branching=3, root_branching=None, dedup='level', beam=None, path_score='raw')

RDR(H, b): from the root, every state selects up to b candidates; each selection becomes a child that appends the document to its parent's observations.

Parameters

  • depthintdefault 4

    H, encoded levels including the root (paper: 4).

  • branchingintdefault 3

    b, selections per state (paper: 3).

Advanced parameters (4)
  • root_branchingint | Nonedefault None

    Selections of the root (defaults to branching).

  • dedupstrdefault 'level'

    "level" (merge per level, exclude earlier levels; multi-hop), "none" (single-hop) or "sequential" (legacy). See rdr.search.base.

  • beamint | Nonedefault None

    Keep only the beam best children per level by cumulative path score (beam search).

  • path_scorestrdefault 'raw'

    "raw" (product of raw cosines; paper) or "minmax" (product of full-column min–max normalized scores, the legacy GRITHopper/HippoRAG tree). Only affects path scores.

  • Related: ChainSearch (b = 1), BreadthSearch (H = 2), BeamSearch (pruned tree).
