Search strategies

Which states form

A search strategy decides which states the encoder sees. Each state is rendered as [instruction; query; observed documents] and encoded once. All strategies share one engine: level by level, every state retrieves its top-K candidates, and the strategy picks which of them become children.

Maxima: when branches propose the same document, the multi-hop presets merge them, so fewer states are realized. Rounds are dependent rounds; all states of a level are encoded and searched in one batch. Document-as-query encodes only the root; its children search with the selected documents' own index vectors.

python
from rdr import RecursiveRetriever, TreeSearch, BeamSearch

retriever = RecursiveRetriever("RDR-8B")                  # default: TreeSearch(depth=4, branching=3)
retriever.search(queries, index, search=BeamSearch(width=5))     # per call
retriever.search(queries, index, search="chain")                 # by name
retriever.search(queries, index, search={"name": "tree", "depth": 3, "branching": 3})

One readout for every search

Whatever the search, the default readout is the global readout: every retained candidate of every state is scored by all states. The outputs that prior methods return (a beam's chains, a chain's last state, a promoted document's list) are available as explicit readouts. The paper finds the readout matters more than the search: with the global readout, chain, beam and tree reach 53.9–55.2 mean Recall@5 on four multi-hop suites (Table 3b).

Every search strategy returns the same kind of object, a Traversal with all states, their candidates and the proposals the search made. Any readout can read any traversal; see Search × readout.
