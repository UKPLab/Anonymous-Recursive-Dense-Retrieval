Reproducing the paper

reproduce/ holds one configuration per group of tables. The runner performs one traversal per search and reads it with every readout of those tables, so readouts are compared on identical states (Appendix F). The aggregator prints each value next to the paper's.

Data

The single-hop suites load from the Hugging Face Hub with the paper's repositories, splits, pinned revisions and instruction strings. TopiOCQA and the multi-hop suites read prepared files from --data-root; reproduce/README.md lists their layout. Gold labels follow the paper: supporting paragraphs (MuSiQue), evidence documents (BrowseComp+), and any passage of a relevant source group (FanOutQA, FRAMES).

Exact mode

  • --exact reproduces the paper's batch composition: fixed consecutive encoder batches, states grouped per query (multi-hop) or one encoder call per slot (single-hop). bf16 embeddings depend slightly on which texts share a batch.
  • Budgets as in the paper: query states up to 4096 tokens (2048 in the shallow breadth configuration), documents 512 tokens (multi-hop passages) or 8192 tokens (single-hop corpora).
  • --shard i --num-shards n splits the queries; the aggregator only reports a task when all of its shards are present.

What is not in the package

  • Training and the RRW training data.
  • LLM reranking (Appendix J) and the baselines with other encoders.
  • BRIGHT-Pro, which is scored with the benchmark's official evaluation code.
Scores are compared per cell; the aggregation follows the paper (task macro for NanoBEIR and BRIGHT, 35-group macro for ToolRet, ten-dataset macro for CoIR, query mean for TopiOCQA and the multi-hop suites). See Evaluation.
