Readouts

How states become a ranking

A readout maps one saved traversal to one ranking. It only reads the states' candidates and scores, so any number of readouts can be compared on identical states, without encoding again.

Global (default)

what search() uses unless told otherwise

every retained candidate of every state, level-balanced mean of sparse softmax distributions (Eq. 2)

The global readout is the default for every search, including beam and chain. A realized readout (a beam's chains, a path product, a chain's last state) is used only when you pass it: search(..., readout=ProbabilityChain()). The reference marks these readouts with realized · request explicitly.
python
from rdr import GlobalReadout, PathProduct, ProbabilityChain, RRF, recovery_fusion

traversals = retriever.traverse(queries, index, views=["recovery"])   # one search, all states kept
readouts = {"global": GlobalReadout(), "path product": PathProduct(), "BeamDR": ProbabilityChain(),
            "RRF": RRF(), "+ recovery": recovery_fusion()}
rankings = {name: retriever.read(traversals, index, r) for name, r in readouts.items()}

The readout matters more than the search

Table 3b of the paper reads the same traversals with different readouts (RDR-8B, same index). With the global readout, chain, beam and tree land within 1.3 Recall@5 of each other. Reading the same states by their last state or by path products costs 2.5 (tree), 11.1 (beam) and 21.7 (chain) points.
