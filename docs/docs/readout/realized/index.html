Readouts

Realized paths

The outputs of prior recursive retrievers rank only the documents the search selected (the realized set E), each by the score of its own path. rdr keeps them for comparison. Because the default readout of every search is the global readout, a realized readout is used only when you pass it.
from rdr import PathProduct

# multi-hop
hits = retriever.search(queries, index,
                        readout=PathProduct())
# single-hop protocol: complete with the root
hits = retriever.search(
    queries, index,
    readout=PathProduct(backfill_root=True),
)

ℓ_s(d) = cos(z_s, e_d) of each selection (b = 2 per state): A 0.62, B 0.60 | D 0.66, E 0.60, F 0.60 | G 0.70, H 0.62

  • PathProduct: score(d) = max over selections of d of Π ℓ along the path, the product of raw cosines. Cosines are below one, so the product only shrinks with depth, and the root's picks lead the list.
  • ChainOrder(score): the complete chains (the selections of the deepest level) are sorted by their score and emitted one after another in hop order, skipping duplicates. SequenceSum sums raw cosines (MDR); ProbabilityChain sums the log sparse-softmax probabilities of each hop (BeamDR).
  • TerminalState: the deepest state with the best path score, read alone.
  • backfill_root=True completes a list with the root ranking. The paper's single-hop tables do this before computing nDCG@10.
Realized readouts include the selections of the deepest level and the paths a beam pruned: E is every document some state selected.

rdr.PathProduct

realized · request explicitly"path_product"guide[source]
classrdr.PathProduct(backfill_root=False)

score(d) = max over selections of d of prod_i l_i — the product of the selecting scores along the path (raw cosines, or min–max scores for TreeSearch(path_score="minmax")).

Raw cosines are below one, so a path product can only shrink along a path: the root's picks lead the list.

Parameters

  • backfill_rootbooldefault False

    Complete the list with the root ranking (documents not yet listed, in root order), as the single-hop protocol does before nDCG@10.

rdr.ChainOrder

realized · request explicitly"chain_order"guide[source]
classrdr.ChainOrder(score='logprob', backfill_root=False)

Complete chains in hop order, as returned by beam retrievers.

The complete paths (the selections of the deepest states) are sorted by score and emitted one after another, each in hop order, duplicates skipped:

  • "logprob" — sum of the states' log sparse-softmax probabilities (BeamDR's probability chain),
  • "sum" — sum of raw cosines (MDR's sequence score),
  • "product" — product of raw cosines.

Ties break by the path.

Parameters

  • scorestrdefault 'logprob'

    Path score that orders the complete chains: "logprob", "sum" or "product".

  • backfill_rootbooldefault False

    Complete the list with the root ranking (documents not yet listed, in root order), as the single-hop protocol does before nDCG@10.
