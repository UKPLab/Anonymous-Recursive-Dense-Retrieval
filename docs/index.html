Recursive Dense Retrieval

Anonymous authors

Paper under double-blind review

Single-hop refinement, multi-hop evidence chains and broad coverage all decide, at every step, what to search for next and how to organize what was found — yet each is trained and searched in its own way. RDR unifies them with one instruction-conditioned encoder that maps a retrieval goal and the artifacts observed so far to the next query embedding. Repeated lookups in a fixed index build a retrieval tree, and a global readout ranks every candidate by the scores of all its states. Trained on Recursive Retrieval Worlds (4.75M samples), RDR-8B reaches 80.14 Recall@5 on MuSiQue, beats state-of-the-art encoders and multi-hop retrievers on all four multi-hop benchmarks, and lifts its own single-hop mean by 2.5 nDCG@10 — on average 5.8 Recall@5 and 3.6 nDCG@10 above the strongest baselines.

The operator

Retrieval as a recursive transition

Finding a first match is often only the beginning: an observed document reveals a missing fact, a conversation changes the need, a near miss shows what the next search should rule out. Today that update usually happens in an agentic loop, where a language model reads the results and writes the next query — an extra generative model at every step, and a split between retrieving evidence and deciding how to update the search. RDR asks whether the retriever itself can learn the update. Its core is one operator, applied again and again.

  1. z_s = f_θ([ι; q; ctx(O_s)])Encode

    One instruction-conditioned encoder reads the state — an instruction ι, the query q and every observed document, all as text — and predicts the next query embedding. Nothing is generated: no subquery, no decomposition, no LLM in the loop.

  2. ℓ_s(d) = cos(z_s, e_d)Retrieve

    The embedding searches a fixed index of cached document vectors. Documents are never re-embedded, so the index grounds each prediction in an artifact that actually exists.

  3. O_s′ = O_s ∪ {d}Update

    A retrieved document is appended to the state as text and the same encoder is called again. Because the instruction is part of the state, it decides what the next call looks for.

Continuation instruction

asks for still-missing evidence given the observations: “Given the question and the documents already retrieved, retrieve the next document needed to continue answering it.” It drives evidence chains and coverage — multi-hop depth and width — and aspect-aware BRIGHT-Pro.

Recovery instruction

revisits the observations to better match the original goal: “The previously retrieved document is a distractor or partial observation. Given the query and this document, retrieve the document that fully satisfies the information need.” It drives relevance refinement on single-hop suites.

Same encoder, same weights, same index — only the instruction in the state changes. Both roles use the same update at every depth, and both are strings from the training mixture, shared across suites.

The setting

Everything becomes an observation

Modern embedding models retrieve far more than Wikipedia paragraphs: web pages, conversations, code, SQL, tool descriptions, tables. RDR serializes every one of them as text and embeds them into one fixed index, so any retrieved artifact can become an observation in the next state — and the next hop can land on a different kind of artifact without the retriever having to know in advance.

One index, one geometry. A tool description and a paragraph of prose do not become the same kind of object — they become comparable ones, and they are interleaved throughout the line rather than partitioned by medium.

Three task families, three separate toolkits

Single-hop feedback improves relevance, a multi-hop question continues an evidence chain, and a broad query collects complementary evidence. Each line of work develops its own encoder training, its own search update and its own readout, tailored and evaluated for one family — and none has shown that it generalizes across scenarios or artifact types.

Prior work, one family each

Single-hop · test-time refinement
ANCE-PRF, DC-PRF

Pseudo-relevance feedback re-encodes retrieved passages into one query vector, or refines a frozen encoder's vector and interpolates it with the root. The update is not trained for recursion.

Multi-hop depth · decomposition-free retrieval
MDR, BeamDR, GRITHopper

They learn chained updates, but return realized paths: a document scored but not selected is discarded, and each returned document is scored only by its own chain.

Multi-hop width · search and aggregation
COR, MMR, JPR, CoveR

They fuse ranked lists or select covering evidence — but the lists come from parallel views that no learned update connects.

What RDR adds

One learned operator for every scenario

A single instruction-conditioned encoder refines single-hop queries over documents, dialogues, code and tools, follows evidence chains and collects complementary evidence — with a fixed index and no generated text.

A global readout over sequentially composed states

Every retained candidate is scored by all states of the retrieval tree, so a document that several states score highly ranks high even if no path selected it. Crossing searches with readouts shows the readout, not the search, is decisive.

Training states that look like test-time states

Recursive Retrieval Worlds puts 4.75M samples into one instruction–query–observation–target format; 43% already carry observed documents, the kind of state tree search produces.

The mechanism

One tree search, two instructions, one readout

Turning the loop repeatedly builds a retrieval tree. RDR(H, b) starts from the empty-context root and evaluates up to H levels; every expandable state selects b documents, and each child appends one of them to its parent’s observations. RDR(4, 3) — up to 1 + 3 + 9 + 27 = 40 query states — is the operating point for every task. What changes between multi-hop and single-hop retrieval is only the instruction written into the states.

1 · Keep turning the loop — multi-hop depth and width

With the continuation instruction, each state asks for the evidence still missing given what it has observed. Depth follows one chain further; width lets different branches collect complementary evidence. The same tree serves MuSiQue and BrowseComp+ (chained evidence) and FanOutQA and FRAMES (coverage): RDR(4, 3) improves over its own root by 21.63, 8.41, 9.15 and 10.63 Recall@5 and exceeds GRITHopper on all four.

2 · Single-hop — the same tree with the recovery instruction

Single-hop retrieval runs the identical search; the states just carry the recovery instruction, which treats each observed document as a possible distractor or partial match and asks for the document that fully satisfies the original need. The tree improves RDR’s own root on all five suites (+2.50 mean nDCG@10), most on conversational retrieval (+7.42 on TopiOCQA); run through the same tree, the stock initialization loses 1.35.

3 · Read out the whole tree, not a path

Each state keeps its top-200 candidates as a sparse softmax distribution (τ = 0.05); RDR averages these within each level and then across levels, so a document ranks high when many states retrieve and score it — including documents no path selected, and documents that earlier states found and later states re-score. Recursive retrievers instead score a document by the path that reached it. Under one encoder, the readout matters more than the search:

Recursive Retrieval Worlds

Training data

Supervised multi-hop training data has so far come from Wikipedia: MuSiQue, HotpotQA, 2WikiMultiHopQA, HoVer and EX-FEVER — the five training sets of GRITHopper — are all chains of Wikipedia paragraphs, and MDR and BeamDR train on two-hop Wikipedia chains. Evaluation moved on: public benchmarks now draw on the open web, conversations, code and tool descriptions. RRW therefore builds training states over heterogeneous environments — persona-seeded web worlds, synthetic company worlds, dialogue- and document-conditioned tasks, and recovery versions of code, SQL, tool-call and chat retrieval — and puts them, together with the existing data, into one instruction–query–observation–target tuple, so that training states look like the states tree search produces.

Prior supervised training data

Wikipedia only: evidence chains of up to four paragraphs (MuSiQue, HotpotQA, 2WikiMultiHopQA, HoVer, EX-FEVER), two hops for MDR and BeamDR.

Web pages, company documents, dialogues, code, SQL and tool calls, plus the existing Wikipedia chains — chains and evidence sets up to the 18th document.

    Existing evidence chains

    Multi-hop QA (MuSiQue, HotpotQA, 2WikiMultiHopQA) and fact-checking (HoVer, EX-FEVER), chains of up to four documents. Every successful prefix becomes a state whose target is the next artifact.

  2. 02

    Context lifting

    Reasoning and instruction supervision turned into document- and dialogue-conditioned transitions: Doc-ReasonIR, Chat-ReasonIR and Doc-Promptriever.

  3. 03

    Constructed worlds

    Persona-seeded web worlds and synthetic company worlds supply complementary evidence and constrained chains beyond four documents — 96k of their 341k samples target the 5th to 18th document of a chain or evidence set.

  4. 04

    Recovery supervision

    Any sample, even a plain query–target pair, gets a misleading observation — a hard negative or an out-of-context document — while the target is kept, so the encoder learns to return to the original need. 1.04M samples, including recovery versions of 63 single-hop datasets for code, SQL, tool calls and chat.
